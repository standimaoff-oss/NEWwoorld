# NEWwoorld

Каркас 3D-игры на **Godot 4** с C++-расширением, полным набором проверок и
рабочим конвейером ассетов.

Проект создан по техническому заданию в [`ТЗ.md`](ТЗ.md) — **начинать чтение
нужно с него**. Этот файл описывает только как установить, запустить и
проверить.

---

## Быстрый старт

```bash
git clone --recursive <url>          # подмодули обязательны
cd NEWwoorld
bash tools/setup/setup.sh            # установка окружения (идемпотентно)
bash tools/verify/verify_all.sh      # проверить всё доступное
```

Уже клонировано без подмодулей:
```bash
git submodule update --init --recursive
```

Все команды продублированы в `Makefile`:
```bash
make help        # полный список целей
make setup       # установка окружения
make check       # проверки
make test        # тесты GUT (нужен Godot)
```

## Что нужно для запуска игры

**Godot Engine 4.5 или новее.** Скачать: <https://godotengine.org/download>.

| Что | Без Godot | С Godot |
| --- | --- | --- |
| Статические проверки (линтеры, контракт, данные, гигиена) | ✅ | ✅ |
| Проверка синтаксиса C++ | ✅ | ✅ |
| Конвейер ассетов | ✅ | ✅ |
| **Запуск и отладка игры** | ❌ | ✅ |
| **Тесты GUT** | ❌ | ✅ |
| **Экспорт готовой сборки** | ❌ | ✅ (+ шаблоны экспорта) |
| Полная сборка расширения | ❌ | ❌ (нужен scons и ~1000 единиц трансляции) |

Запуск игры:
```bash
godot --path game                      # открыть в редакторе
godot --path game res://scenes/boot/boot.tscn   # запустить напрямую
```

Прогон тестов:
```bash
make test
# или
godot --headless --path game -s addons/gut/gut_cmdln.gd \
  -gconfig=res://.gutconfig.json -gexit -ginclude_subdirs
```

Первый запуск на чистой машине требует импорта ресурсов:
```bash
godot --headless --path game --import
```

## Проверка кода

```bash
bash tools/verify/verify_all.sh              # всё доступное
bash tools/verify/verify_all.sh --quick      # только линтеры, ~10 секунд
bash tools/verify/verify_all.sh --strict     # предупреждения = ошибки
bash tools/verify/verify_all.sh --with-godot # плюс импорт и прогон GUT
```

Отчёт печатает каждый шаг отдельно и различает **три** исхода:

| Исход | Код | Смысл |
| --- | --- | --- |
| ПРОЙДЕНО | 0 | проверено, нарушений нет |
| ПРОВАЛ | 1…124 | проверено, найдены нарушения |
| ПРОПУЩЕНО | **125** | инструмент недоступен |

Пропуск не считается успехом и выводится отдельной строкой:
«пропущено N — это НЕ «всё хорошо»».

Проверяется 12 аспектов: синтаксис GDScript, форматирование, стиль,
существование API движка, **число и типы аргументов вызовов**, структура сцен
и ресурсов, шейдеры, соответствие C++ и GDScript в разрушении, данные
(JSON/схема настроек/`project.godot`/профили качества), гигиена репозитория,
работоспособность ассет-конвейера и синтаксис C++.

Отдельные инструменты:
```bash
bash tools/lint/lint_gdscript.sh --fix           # формат и стиль + автоправка
python3 tools/lint/godot_scene_check.py --strict # сцены и ресурсы
python3 tools/lint/shader_check.py               # шейдеры
python3 tools/verify/check_backend_contract.py --strict  # C++ ↔ GDScript
python3 tools/verify/check_data.py               # данные
python3 tools/verify/check_repo_hygiene.py       # репозиторий
bash tools/cpp/syntax_check.sh --objects         # C++
```

## Ключевые решения

**`project.godot` генерируется, а не пишется.**
Сериализация `Object(InputEventKey, …)` многословна и строга, а редактор
Godot пересохраняет файл по-своему. Ручная правка молча расходится с
генератором и стирается при следующей генерации.

```bash
python3 tools/setup/generate_project_godot.py --check   # сверить
python3 tools/setup/generate_project_godot.py           # перегенерировать
```

**Разрушение имеет два бэкенда.**
C++ (`NewwoorldFracturer`) с автоматическим переключением на GDScript, если
расширение не собрано. Игра работает без нативной библиотеки — медленнее, но
без падения. Оба бэкенда обязаны возвращать данные одинаковой формы;
соответствие проверяется статически, потому что расхождение уже случалось и
выглядело как «случайные глюки».

**Форма настроек строится из схемы.**
Добавление настройки — одна запись в `settings_schema.gd`; строка в
интерфейсе появляется сама, править сцену не нужно.

**GUT вендоренный, godot-cpp — подмодуль.**
Два разных способа подключения стороннего кода, и выбор не случаен.
`game/addons/gut/` — это конвенция Godot: дополнения ставятся копированием
каталога `addons/` в проект, и игра обязана открываться и запускать тесты без
сети. `gdextension/godot-cpp` — зависимость времени сборки, привязанная к тегу
`godot-4.5-stable`, поэтому закрепляется коммитом подмодуля: версия обязана
совпадать с `compatibility_minimum`.

**Конвейер ассетов проверяет собственную работоспособность.**
24 проверки реально импортируют пакеты, кодируют геометрию обоими кодеками и
прогоняют сквозной цикл на временном файле. `npm install` может отчитаться об
успехе при неработающей нативной зависимости — тогда оптимизация упадёт в
самый неподходящий момент.

**Небо в меню процедурное, а не HDRI.**
2 КБ вместо 4–20 МБ, мгновенная генерация и масштабирование под профиль
качества без перекодирования. Меню открывается первым и часто — задержка там
формирует впечатление о всей игре.

## CI

`.github/workflows/godot-ci.yml`, семь заданий:

| Задание | Что делает | Блокирующее |
| --- | --- | --- |
| `lint` | все статические проверки | ✅ |
| `cpp-syntax` | компиляция C++ до объектных файлов | ✅ |
| `tests` | прогон GUT в реальном Godot 4.5 + загрузочный смоук | ✅ |
| `build-extension` | сборка расширения: Linux ×2, Windows, macOS | ✅ |
| `cmake-smoke` | сборка через CMake + `compile_commands.json` | ✅ |
| `assets` | валидация моделей и атрибуция | ✅ |
| `godot-latest` | тесты на последней версии Godot | ❌ (информационно) |

Тесты прогоняются на **4.5**, а не на последней версии: расширение собирается
против `compatibility_minimum = "4.5"`, и проверять надо старейшую
поддерживаемую версию. Прогон на 4.7 не поймал бы использование API, которого
в 4.5 нет.

Отдельно в CI проверяется то, что не проверяется больше нигде: **каждая
собранная библиотека объявлена в `.gdextension`**. При расхождении имён Godot
не падает и не пишет ошибку — он просто не находит библиотеку, а игра молча
переключается на медленный запасной путь.

## Требования к среде разработки

| Компонент | Версия |
| --- | --- |
| Godot Engine | 4.5+ (целевая 4.7.2-stable) |
| Python | 3.11+ |
| Node.js | 18+ (проверено на 22) |
| gdtoolkit | 4.5.0 (закреплён) |
| SCons | 4.11.1 (закреплён) |
| godot-cpp | тег `godot-4.5-stable` |
| GUT | 9.6.1 |

Версии инструментов закреплены намеренно: плавающая версия линтера означает,
что в один день репозиторий зелёный, а на следующий — красный без единого
изменения в коде.

`bash tools/setup/setup.sh` устанавливает всё перечисленное и идемпотентен:
повторный запуск не ломает существующее окружение. При частичной неустановке
скрипт завершается с кодом 1 и сообщает, что именно не удалось.
