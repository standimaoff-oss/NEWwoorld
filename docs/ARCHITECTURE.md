# Архитектура Aquaflux

Документ для тех, кто будет читать код (и для будущего себя).

## Слои

```
com.standimaoff.aquaflux
├── core        чистый Java, ни одного класса Minecraft, полностью покрыт тестами
│   ├── Precision        пресеты 16/32/64 (квантование высот и скоростей)
│   ├── SolverSettings   параметры решателя (неизменяемые)
│   ├── WaterGrid        сама симуляция: shallow water на шахматной сетке
│   ├── BoundarySource   глубины соседнего региона (шов)
│   └── WaterStats       сводка: масса, скорости, волны, мокрые ячейки
├── world       мост в мир
│   ├── WaterRegion      регион 32×32 блока: сэмплинг пола, скан блоков, запись блоков
│   ├── WaterEngine      бюджет тика, активные регионы, передача массы через шов
│   ├── VanillaReplacer  постепенная замена ванильной воды
│   └── WaterEvents      события Forge → движок
├── fluid       жидкость и её тип
├── block       блок физической воды
├── registry    DeferredRegister'ы
└── client      рендер, палитра, совместимость с шейдерами
```

Ключевое правило: **`core` ничего не знает об игре**. Поэтому решатель можно гонять в тестах
за миллисекунды, а баги физики ловить без запуска клиента.

## Решатель

### Сетка

Состояние ячейки:

- `ground` — абсолютная высота верхней грани твёрдого блока (пол);
- `depth` — глубина воды над полом;
- `u`, `v` — скорости на гранях (шахматная сетка: `u` между ячейками по X, `v` по Z);
- `wave`, `waveV` — визуальные волны (не переносят массу).

Уровень поверхности: `eta = ground + depth`.

### Шаг

1. **Разгон.** Для каждой грани `du/dt = -g · Δeta / dx`, трение
   `f = bedFriction / max(0.15, h) + turbulence·|u|`, полунеявное интегрирование:
   `u ← (u − dt·g·Δeta/dx) / (1 + dt·f)`, ограничение `|u| ≤ maxSpeed`.
2. **Объём через грань.** `V = u · h_upwind · dx · dt`, где `h_upwind` — глубина ячейки-донора
   (перенос вверх по потоку, как в клеточных автоматах).
3. **Ограничение оттока.** Для каждой ячейки сумма уходящих объёмов не может превышать 85%
   её запаса. Если превышает — все её исходящие грани масштабируются одним множителем
   (скорость тоже, чтобы импульс не обгонял массу). Это гарантирует `depth ≥ 0`.
4. **Применение.** `depth ± V/area`. Схема консервативна: сколько ушло через грань, столько
   и пришло.
5. **Границы.** Внешняя грань отдаёт массу только наружу; приход приходит от соседнего региона,
   который сам посчитал свой отток. Каждая грань управляется ровно одной стороной, поэтому
   двойного счёта нет.
6. **Волны.** Отдельное затухающее волновое уравнение по 4 соседям, шаг ограничен CFL
   для скорости волн.

### Устойчивость

Шаг разбивается на подшаги по CFL:

```
dt_gravity = 0.45 · dx / sqrt(g · max(h, 0.25))
dt_waves   = 0.35 · dx / (c · sqrt(2))
```

Число подшагов ограничено `maxSubsteps` (6). При `cellSize = 0.5` и глубине до 32 блоков
на тик уходит 2–6 подшагов.

### Точность 16 / 32 / 64

После шага глубины и скорости квантуются:

| Пресет | Шаг высоты | Шаг скорости | Эффект |
|---|---|---|---|
| 16 | 1/256 блока | 1/64 | вода «залипает» в спокойном состоянии, регион раньше засыпает |
| 32 | float | float | рабочий режим |
| 64 | нет | нет | максимум точности |

Квантование заодно работает как фильтр шума: мелкая рябь исчезает и не жжёт TPS.

## Регионы и производительность

- Регион — 32×32 блока, внутри сетка 64×64 (при `cellSize = 0.5`).
- Активны только регионы в радиусе `activeRadius` вокруг игроков.
- За тик считаются `regionsPerTick` регионов (по умолчанию 4), блоки обновляются в одном.
- Регион с нулевой массой не считается вовсе.
- Спокойный регион (`maxSpeed` и `maxWave` ниже порога несколько тиков) засыпает: волны
  дополнительно гасятся.
- Пол сэмплируется один раз при создании региона и точечно обновляется после копки/строительства
  (очередь ограничена 2048 позициями, 128 за тик).

### Запись в мир

Глубина переводится в блоки: полные блоки + верхний блок с `level` (1/8 шага).
`lastTop` на колонку не даёт оставить «висящие» блоки, когда вода ушла. Флаг `APPLYING`
не даёт движку принять собственные изменения за действия игрока.

### Восстановление после перезапуска

Отдельного файла сохранений нет: масса восстанавливается сканированием блоков физической воды
в регионе при его создании. Мир сохраняет блоки — мод восстанавливает из них глубину.

## Рендер

1. Хайтмапа `MOTION_BLOCKING` учитывает жидкости, поэтому верх воды находится за один запрос.
2. Верхний блок даёт дробную высоту через свойство `level`.
3. Углы квадов усредняются по четырём колонкам → гладкая поверхность; нормали — по градиенту.
4. Там, где сосед сухой, рисуется бортик вниз до дна блока — нет «пустоты» под водой.
5. Цвет считается по глубине и наклону нормали, квантуется под пресет битности.
6. Волны от игроков добавляются при отрисовке как затухающие кольца — меш не перестраивается.
7. Меш перестраивается раз в `rebuildInterval` кадров или при сдвиге игрока на 2+ блока.

## Совместимость

- Никаких миксинов: только Forge-события, свои блок/жидкость/предмет.
- `RenderCompat` мягко ищет Iris (`IrisApi`) и OptiFine (`Shaders.shaderPackLoaded`) через
  рефлексию; если класс не найден — это нормальный путь, а не ошибка.
- В режиме `AUTO` поверхность остаётся своей, но рисуется ванильным `entityTranslucent`,
  который шейдерпаки обрабатывают штатно.
