# Конвейер ассетов

Оптимизация и валидация 3D-моделей до того, как они попадут в игру.

Расположение: `tools/asset-pipeline/`. Требует Node.js 18+ и
`npm ci` один раз.

---

## Зачем конвейер, если Godot сам импортирует

Godot импортирует почти любой glTF, **включая сломанный**. Модель с
отрицательным масштабом узла выворачивается наизнанку, материал без PBR
становится белым пластиком, текстура 8192×8192 занимает 256 МБ
видеопамяти. Ни одно из этого не считается ошибкой импорта — игра просто
выглядит плохо, а причину ищут в движке, хотя она в файле модели.

Конвейер делает две вещи: приводит модель к бюджетам и **отказывается
принимать** то, что в бюджет не влезает.

---

## Команды

```bash
cd tools/asset-pipeline && npm ci     # один раз

# оптимизировать все модели в каталоге
node scripts/optimize_models.mjs ../../game/assets/models

# валидировать (в CI — со --strict)
node scripts/validate_models.mjs ../../game/assets --strict

# проверить работоспособность самого конвейера
node scripts/check_pipeline.mjs
```

Через `make` из корня: `make assets-optimize`, `make assets-validate`.

### Ключи `optimize_models.mjs`

| Ключ | По умолчанию | Смысл |
| --- | --- | --- |
| `--target=meshopt\|draco` | `meshopt` | Кодек сжатия геометрии |
| `--ratio=N` | `1.0` | Доля треугольников после упрощения; `1.0` = не упрощать |
| `--error=N` | `0.01` | Допустимая погрешность упрощения |
| `--max-texture=N` | `2048` | Предельный размер текстуры; `0` = не трогать |
| `--webp` / `--ktx2` | `--webp` | Формат текстур |
| `--no-quantize` | квантование включено | Отключить квантование атрибутов |
| `--out=dir` | на месте | Каталог результата |

### Выбор между meshopt и draco

| | `EXT_meshopt_compression` | `KHR_draco_mesh_compression` |
| --- | --- | --- |
| Распаковка | быстрее | медленнее |
| Степень сжатия | умеренная | выше |
| Статус в glTF | расширение (не Khronos) | расширение Khronos |
| Godot 4 | поддерживается | поддерживается |

Для игры с частой подгрузкой — `meshopt`. Для архива или статичного
контента — `draco`. **Оба сразу включать нельзя**: валидатор это ловит.

## Порядок преобразований

Порядок выведен из исходников пакетов и проверен измерением, а не взят из
документации. Три неочевидных места — каждое стоило времени:

**1. `simplify` требует сваренную геометрию, `tangents` — разваренную.**

`simplify()` на неиндексированной геометрии рвёт меш на несвязные куски.
А `tangents()` пропускает любой примитив, у которого **есть** индексы:
в исходниках пакета (`filterPrimitive`) прямо написано
*«primitives must be unwelded»*. Между двумя шагами обязателен переход.

`normals()` разваривает сам (внутри вызывает `unweld()`), но запускается
только когда нормалей нет. Если нормали уже были, разваривание нужно делать
явно — иначе тангенты молча не посчитаются, а в логе останется только
`No qualifying primitives found`.

Проверка результата, а не отсутствия исключения, закреплена в
`check_pipeline.mjs` шагом «тангенты реально появляются в файле».

**2. `reorder` требует сваренную геометрию.**

На разваренной печатает `No qualifying primitives found; may need to weld
first` и ничего не делает — порядок вершин остаётся неоптимальным для кэша,
и модель медленнее рисуется без всякой ошибки.

**3. Квантование идёт ПОСЛЕ переупорядочивания.**

Измерено на модели 800 треугольников с текстурой 1024×1024:

| Порядок | Результат |
| --- | --- |
| `quantize → reorder` | 693 948 байт, `reorder` предупреждает |
| `weld → reorder → quantize` | 679 044 байт, предупреждений нет |

Квантование меняет значения атрибутов и может пересчитать вершины, отменив
кэш-оптимальный порядок треугольников.

Итоговая цепочка:

```
flatten → dedup → prune → weld → [simplify]
        → [normals] → [unweld] → [tangents]
        → textureCompress → weld → reorder → quantize
        → meshopt | draco
```

Шаги в квадратных скобках выполняются по фактическому состоянию модели, и
пропуск **объясняется в отчёте**:
```
· рассчитаны плоские нормали (в файле их не было)
· рассчитаны тангенты (MikkTSpace)
```
Молчаливый пропуск шага неотличим от поломки, поэтому каждый пишет строку.

## Текстуры: WebP, а не KTX2

Формально KTX2/Basis лучше: текстура остаётся сжатой в видеопамяти и
декодируется на GPU. Но кодирование в KTX2 требует внешнего набора
инструментов KTX-Software (`toktx`, `basisu`), которого нет ни в среде
разработки, ни в стандартном CI-раннере.

WebP кодируется установленным `sharp`, поддерживается Godot 4 нативно и даёт
25–40 % экономии против PNG. KTX2 включается флагом `--ktx2`, когда тулчейн
доступен.

**Однотонные текстуры удаляются.** `prune({ keepSolidTextures: false })`
заменяет их константным `baseColorFactor`. Это не потеря данных: плоский
цвет как текстура занимает килобайты и требует выборки из памяти на пиксель.

## Бюджеты валидации

| Что | Предел | Действие при превышении |
| --- | --- | --- |
| Размер файла | 12 МБ | ошибка |
| Размер файла (рекомендация) | 4 МБ | предупреждение |
| Треугольников в модели | 250 000 | ошибка |
| Треугольников (>60 % бюджета) | 150 000 | предупреждение |
| Вершин | 200 000 | ошибка |
| Текстур в модели | 32 | ошибка |
| Сторона текстуры | 4096 px | ошибка |
| Узлов | 512 | предупреждение |

Числа соответствуют `Validators.MAX_MODEL_BYTES` и `MAX_TEXTURE_BYTES` в
`game/scripts/util/validators.gd`. Расхождение между ними проверяется
тестом `test_validators.gd`.

Кроме размеров валидатор ловит:

- ошибки спецификации glTF 2.0 (официальный валидатор Khronos);
- `KHR_materials_pbrSpecularGlossiness` — устарело, Godot 4 конвертирует с
  потерями;
- отсутствие сжатия геометрии при >1000 треугольников — верный признак, что
  файл не проходил конвейер;
- оба сжатия одновременно;
- отрицательный масштаб узла — выворачивает нормали: модель выглядит целой,
  но освещается как вывернутый носок;
- нулевой масштаб — узел не отрисуется вообще;
- пробелы и не-ASCII в именах узлов — `get_node()` ищет по точному имени, а
  экспортеры заменяют пробелы или кодируют их, в результате обращение молча
  возвращает `null`;
- PNG крупнее 1 Мп — предложение конвертировать;
- двусторонний материал — каждый треугольник рисуется дважды.

## `check_pipeline.mjs`: 24 проверки

Отвечает не на «установлен ли пакет», а на **«работает ли он»**. Конвейер
состоит из восьми пакетов с нативными зависимостями (`sharp`, `draco3dgltf`,
`meshoptimizer`); любой может не собраться под платформу, при том что
`npm install` отчитается об успехе.

Проверяется: импорт каждого пакета, создание документа glTF в памяти, цикл
запись/чтение GLB, кодирование и **декодирование** Draco, сварка и
упрощение, кодирование текстур, валидатор Khronos, форма отчёта `inspect()`,
и сквозной прогон полного конвейера на временном файле.

Две проверки существуют потому, что соответствующие ошибки уже случились:

**«meshopt: энкодер и декодер различаются».** `MeshoptEncoder` нельзя
подставить на место декодера: у него нет метода `decodeGltfBuffer`. Установка
зависимостей проходит успешно, а падение случается позже — при повторном
прогоне конвейера по уже сжатой модели — и с сообщением
`decodeGltfBuffer is not a function`, из которого причина неочевидна.

**«повторный прогон по уже сжатой модели».** Оптимизировать, записать,
прочитать обратно, оптимизировать снова. Обычный сценарий: художник
пересохраняет модель из DCC поверх уже обработанной.

## Ошибки, найденные при написании конвейера

Все они обнаружены собственными проверками, а не в бою. Каждая зафиксирована
комментарием в коде на месте возникновения.

| Ошибка | Симптом | Причина |
| --- | --- | --- |
| `simplifyor` вместо `simplifier` | `simplifier dependency required — install "meshoptimizer"` | Опечатка в имени ключа не ловится синтаксически — лишний ключ просто игнорируется |
| `readBinary(ArrayBuffer)` | `Method requires Uint8Array parameter; received "object"` | `NodeIO.readBinary` принимает `Uint8Array`. Передавать `.buffer` нельзя и по другой причине: это взгляд на весь выделенный пул, заголовок glTF читается со смещения |
| `tangents()` без `mikktspace` | `generateTangents callback required` | Зависимость не транзитивная, объявлена в `package.json` явно |
| `MeshoptEncoder` как декодер | `decodeGltfBuffer is not a function` | Энкодер и декодер — разные объекты с разными методами |
| `inspect()` → `report.primitives` | `undefined` | В 4.5.1 отчёт — это `{scenes, meshes, materials, textures, animations}`, каждый раздел со списком `.properties`; поля `primitives` на верхнем уровне нет |
| `tangents()` после `weld()` | `No qualifying primitives found` | Шаг требует разваренную геометрию |
| `reorder()` после `quantize()` | `No qualifying primitives found; may need to weld first` | Шаг требует сваренную геометрию |
| `validator.version` | печатает `() => validator.version()` | У `gltf-validator` это **функция**, у `@gltf-transform/core` — строка |

## Добавление модели в игру

1. Положить исходник в `game/assets/models/source/`.
2. Оптимизировать:
   ```bash
   node tools/asset-pipeline/scripts/optimize_models.mjs \
     ../../game/assets/models --ratio=0.8
   ```
3. Валидировать:
   ```bash
   node tools/asset-pipeline/scripts/validate_models.mjs ../../game/assets --strict
   ```
4. Если модель сторонняя — записать в `game/assets/ATTRIBUTION.md` и в
   `game/data/credits.json` → `used_assets`.
5. `python3 tools/verify/check_data.py` — сверит два файла атрибуции.
6. Крупные файлы уходят в Git LFS автоматически: `.gitattributes` покрывает
   `glb`, `gltf`, `fbx`, `blend`, `ktx`, `psd`, `kra`.
