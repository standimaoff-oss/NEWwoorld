## Три правила, которые важнее любой документации

**1. `game/project.godot` не редактируется руками.**
Файл генерируется скриптом `tools/setup/generate_project_godot.py`. Ручная
правка молча сотрётся при следующей генерации. Проверка расхождения:
```bash
python3 tools/setup/generate_project_godot.py --check
```

**2. Ни одна проверка не должна быть «примерно зелёной».**
Каждый инструмент различает три исхода: пройдено, провалено и
**инструмент недоступен** (код 125 в `verify_all.sh`). Последний считается
пропуском, а не успехом, и выводится отдельной строкой в итоговом отчёте.
«Пропущено 3» — это не «всё хорошо».

**3. Перед коммитом — одна команда.**
```bash
bash tools/verify/verify_all.sh --strict
```
Она выполняет всё то же, что выполняет CI. Если локально зелёное, а в CI
красное, значит расхождение между ними — само по себе баг, который нужно
чинить, а не обходить.
