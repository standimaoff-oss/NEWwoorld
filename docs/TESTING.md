# Тестирование

Тесты написаны на [GUT 9.6.1](https://github.com/bitwes/Gut) и лежат в
`game/tests/`. Их запуск требует бинарник Godot.

---

## Запуск

```bash
# всё сразу (если Godot установлен)
bash tools/verify/verify_all.sh --with-godot

# только тесты
make test

# одна категория
make test-unit
make test-integration
make test-smoke

# один файл
godot --headless --path game -s addons/gut/gut_cmdln.gd \
  -gtest=res://tests/unit/test_game_config.gd -gexit
```

Прямая команда:
```bash
godot --headless --path game \
  -s addons/gut/gut_cmdln.gd \
  -gconfig=res://.gutconfig.json \
  -gexit -ginclude_subdirs
```

Флаги значимы:

| Флаг | Зачем |
| --- | --- |
| `--headless` | Без дисплея. На CI и в контейнере другого варианта нет |
| `-gexit` | **Завершить процесс с кодом, отражающим результат.** Без него GUT печатает «FAILED», а процесс выходит с нулём — CI остаётся зелёным при падающих тестах |
| `-ginclude_subdirs` | Обойти `unit/`, `integration/`, `smoke/`, а не только корень |
| `--path game` | Корень проекта — `game/`, а не репозиторий |

Первый запуск на чистой машине требует импорта:
```bash
godot --headless --path game --import
```
Без него каталог `.godot/imported` пуст, и загрузка любого `.png` или `.glb`
в тесте падает с ошибкой, не имеющей отношения к проверяемому коду.

## Категории

Три каталога — три разных вопроса.

### `unit/` — «правильна ли логика»

| Файл | Что ловит |
| --- | --- |
| `test_validators.gd` | 24 случая: пути, лицензии, размеры ассетов |
| `test_settings_schema.gd` | Схема настроек непротиворечива: у каждого ключа тип, диапазон и значение по умолчанию |
| `test_game_config.gd` | Слои физики идут подряд 1..N и не выходят за 32; маска игрока включает мир и взаимодействуемое, но НЕ включает самого игрока; высота глаз меньше роста; капсула не ниже двух радиусов; перевод громкости дБ ↔ линейная обратим; бюджеты разрушения положительны |
| `test_credits_data.gd` | Титры полны: разделы, контакты, лицензии; каждый контакт одного из видов `email\|url\|text\|repo\|chat`; есть хотя бы один reachable-канал; ни одного ассета под запрещённой лицензией |
| `test_project_integrity.gd` | 11 autoload и 30 input action на месте; главная сцена — boot; каждый `res://`-путь существует; на критичных действиях есть И клавиатура, И геймпад; `pause` не совпадает по коду с движением |
| `test_debug_overlay_contract.gd` | Ключи, которые оверлей читает из снимка метрик, действительно в нём есть |
| `test_settings_service.gd` | Все 39 ключей инициализируются; неизвестный ключ отвергается; значения зажимаются в диапазон; сохранение → изменение → загрузка даёт исходное; сигнал уходит только при реальном изменении |
| `test_destruction_service.gd` | Выбор бэкенда; ключи кусков уникальны и содержат обязательные; нулевая энергия безопасна; обломки создаются в нужной группе; число активных обломков не превышает бюджет; 10 вызовов подряд не текут |
| `test_menu_backdrop_budget.gd` | Фон меню в бюджете: ≤512 узлов, ≤500 000 треугольников, ≤2 теневых источника; корень `Node3D`; есть камера и окружение; небо процедурное |

### `integration/` — «работают ли части вместе»

`test_settings_form.gd`: число строк формы равно числу ключей раздела; класс
виджета соответствует типу настройки; значения виджетов равны значениям
сервиса; изменение `CheckBox` и `HSlider` доходит до `SettingsService`; у
каждой строки есть подпись; все виджеты получают фокус (без этого меню
неуправляемо с клавиатуры и геймпада).

### `smoke/` — «загружается ли вообще»

`test_scenes_load.gd`: 11 сцен грузятся как `PackedScene`; 23 скрипта
загружаются и `reload()` возвращает `OK`; 7 ресурсов на месте; 6 шейдеров
не пусты; бюджеты профилей качества не убывают от low к ultra; окружение по
умолчанию не «чистый цвет»; схема аудиоканалов содержит все имена из
`GameConfig.AUDIO_BUSES`; тема содержит размер шрифта подписей и 8 именованных
вариаций.

## Что тесты НЕ проверяют

Это важнее списка того, что проверяют.

**Тесты не запускают игру.** Смоук-тест грузит сцены как ресурсы, но не
проходит путь `boot → menu → world`. Этот путь проверяется отдельно в CI
(задание `tests`, шаг «Загрузочный смоук») запуском движка с
`--quit-after 300`.

**Тесты не проверяют картинки.** «Красиво» и «не AI slop» — требования ТЗ,
но они не формализуются в assert. Косвенно их прикрывают бюджеты
(`test_menu_backdrop_budget.gd`) и проверка, что небо процедурное, а не
четырёхмегабайтная панорама.

**Тесты не проверяют C++ напрямую.** Нативный слой недоступен, если
расширение не собрано. Проверяется форма контракта — статически, через
`tools/verify/check_backend_contract.py`, а не в рантайме.

**Тесты не проверяют производительность.** Есть бюджеты (числа), но нет
замеров на реальном железе: на CI раннер каждый раз разный, и порог
«не медленнее 16 мс» давал бы то зелёный, то красный прогон без изменений
в коде.

## Как писать новый тест

```gdscript
extends GutTest

## Проверяет, что <конкретное поведение>.
##
## Ловит класс ошибок: <какой>. Без этого теста ошибка проявилась бы как
## <симптом в игре>.
func test_something_meaningful() -> void:
	var service: SettingsService = SettingsService
	var snapshot: Dictionary = service.snapshot()
	# Изменяем состояние и обязательно возвращаем. Без восстановления
	# этот тест ломает все следующие — и падают они, а не он.
	_add_teardown(snapshot)

	assert_eq(service.get_int("rendering/msaa"), 2,
		"MSAA по умолчанию обязан быть 2 — см. game/resources/quality/")
```

Правила, каждое из которых стоит за реальной поломкой:

1. **Каждый файл начинается с комментария о том, какой класс ошибок он
   ловит.** Тест без внятного ответа на «зачем» проверяет реализацию, а не
   поведение, и ломается при любом рефакторинге.
2. **Состояние autoload восстанавливается.** `SettingsService` живёт весь
   прогон; изменивший его тест обязан вернуть исходное в `after_each` или
   через снимок.
3. **`apply_now = false`** при установке значений в тестах: иначе каждое
   присваивание пересобирает окружение, и прогон длится минуты.
4. **Не выдумывать assert-функции.** В GUT 9.6.1 нет `assert_dir_exists`.
   Есть: `assert_file_exists`, `assert_file_does_not_exist`,
   `assert_file_empty`, `assert_file_not_empty`, `assert_eq`, `assert_ne`,
   `assert_gt`, `assert_gte`, `assert_lt`, `assert_lte`, `assert_between`,
   `assert_almost_eq`, `assert_true`, `assert_false`, `assert_has`,
   `assert_does_not_have`, `assert_typeof`, `assert_string_contains`,
   `assert_eq_deep`, `assert_not_null`, `assert_signal_emitted`,
   `assert_signal_not_emitted`, `fail_test`, `pending`, `watch_signals`,
   `add_child_autofree`. Хуки: `before_all`, `before_each`, `after_each`.
5. **Незавершённое помечать `pending()`, а не комментировать.** Пример в
   проекте: `test_credits_data.gd` вызывает `pending()` для
   `res://assets/ATTRIBUTION.md`, пока файла не было. Комментарий сделал бы
   проверку невидимой, а `pending` показывает её в отчёте.

## Конфигурация

`game/.gutconfig.json` задаёт каталоги и суффиксы. Проверка, что каталоги
существуют и содержат тесты, — в `tools/verify/check_data.py`. Это не
паранойя: GUT при пустом каталоге молча сообщает «0 тестов, 0 падений» и
выходит с нулём. CI дополнительно требует, чтобы в логе было больше сотни
прохождений — иначе зелёный прогон без единого выполненного теста неотличим
от настоящего.
