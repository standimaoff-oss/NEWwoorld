# Данные, лицензии и обучение

## Принцип: данные не скачиваются неявно

`training.prepare_data` читает только текстовые файлы, которые пользователь уже положил в `data/raw` или передал через `--input-dir`. Так pipeline не выдаёт случайное скачивание, веб-скрейпинг или нарушение лицензии за «обучение с нуля».

Перед добавлением каждого источника создайте запись о:

1. названии набора и URL/версии;
2. лицензии, допустимости обучения и распространения производных весов;
3. дате получения, хеше исходного архива и фильтрах;
4. удалённых персональных данных, токсичном/вредоносном контенте и дубликатах;
5. требуемой атрибуции.

Сохраните manifest рядом с данным, но не добавляйте многогигабайтные корпуса или веса в Git.

## Рекомендуемая структура приватного корпуса

```text
data/raw/
  00_licences.jsonl
  wikipedia_clean.txt
  books_permitted.txt
  dialogue_permitted.txt
  technical_permitted.txt
```

Каждая строка в `.txt` — самостоятельный документ или логичный абзац. В `prepare_data.py` пробелы нормализуются, пустые строки пропускаются, а границы строк отмечаются BOS/EOS токенами. Не смешивайте в одном файле недокументированные источники с разрешёнными.

## Подготовка

```bash
python -m training.prepare_data \
  --input-dir data/raw \
  --output artifacts/ru-v1 \
  --config configs/neuroyadro_25m.json
```

В `artifacts/ru-v1/manifest.json` фиксируются хеши входов, токенизатора и tensor-файла. Этот manifest нужен при любом сравнении запусков.

`tokenizer.model` необходимо хранить вместе с checkpoint: другая BPE-сегментация при тех же числовых ids полностью ломает модель.

## Обучение с короткими сессиями

```bash
python -m training.train \
  --config configs/neuroyadro_25m.json \
  --dataset artifacts/ru-v1/tokenized.pt \
  --output runs/ru-v1 \
  --steps 5000 --batch-size 2 --grad-accum 8 \
  --checkpoint-every 100 --log-every 10 --resume auto
```

- `--steps` — конечный номер шага, поэтому после остановки достаточно повысить его и оставить `--resume auto`.
- CPU подходит для синтаксического и интеграционного smoke-test, но не для быстрого качественного обучения 25M-модели.
- Перед полноценным запуском зафиксируйте версию PyTorch, ОС, тип GPU/CPU и все аргументы. `run.json` делает это автоматически.
- Следите за loss, ручными русскими промптами, повторяемостью, памятью и скоростью токенов. Падение loss само по себе не доказывает полезность диалога.

## Экспорт и проверка

```bash
python -m tools.verify_checkpoint \
  --checkpoint runs/ru-v1/checkpoints/latest.pt
```

Только затем запускайте `training.export_hf` и `training.export_gguf`. Для regression-тестов храните небольшую таблицу фиксированных промптов и ожидаемых *свойств* ответа, а не единственную заранее заготовленную фразу.

## Честные ожидания

Архитектура около 25M параметров — полезный обучающий и офлайн-проект, но не замена современной большой модели. Она может освоить частые русские конструкции и простые продолжения после достаточного качественного корпуса, однако не гарантирует актуальные знания, надёжное рассуждение или безопасные ответы. В приложении такие ограничения должны быть видны пользователю.
